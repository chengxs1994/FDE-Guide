# 把“客户说不清的问题”，变成能用的系统

假设一家网店说：“客服每天都在重复查订单、解释退款，太忙了。”FDE 不会立刻开始写聊天机器人，而会先看客服实际怎样处理一张工单。

观察真实流程→ 明确小目标→ 做出最小版本→ 接入工作环境→ 测量并改进

| 要做的事 | 工单助手里的具体动作 |
| --- | --- |
| 理解业务 | 问客服：最近一次退款咨询，你打开了哪些系统？哪一步最费时间？ |
| 缩小范围 | 第一版只帮助生成“退款咨询”的回复草稿，先由客服审核。 |
| 连接数据 | 读取订单状态、退款规则和用户问题，区分已知事实与缺失信息。 |
| 实现与上线 | 让客服能提交问题、查看依据、编辑草稿；失败时能继续人工处理。 |
| 检验效果 | 比较使用前后的处理时间、事实错误数量和客服采纳情况。 |

**你最终交付的是“能完成工作的流程”。**一段代码、一场演示或一份方案，都是过程中的产物。岗位理解参考 [FDE Practical Guide](https://github.com/abhishekbhartiind/forward-deployed-engineer)。

## 先学什么，后学什么？

先练三件事：**问清楚问题、做出一个小工具、证明它真的有用**。开始时不必同时学习多个 Agent 框架、复杂云架构或模型训练。需要哪项能力，再补对应知识。
