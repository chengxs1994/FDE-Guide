# 先认识这 8 个词，就能看懂大部分入门材料

| 术语 | 用大白话解释 | 在本项目里的用途 |
| --- | --- | --- |
| LLM / 大语言模型 | 能理解和生成文字的模型，输出仍可能出错。 | 把事实和规则组织成回复草稿。 |
| Prompt / 提示词 | 给模型的任务说明、上下文和输出要求。 | 要求“只能使用给定信息，不足时说明”。 |
| API / 接口 | 程序之间约定好的沟通入口。 | 程序调用订单系统，获取订单状态。 |
| JSON | 一种用字段名称和值表示数据的格式。 | `{"order_id":"A1001","status":"未发货"}` |
| RAG / 检索增强生成 | 先找相关资料，再把资料交给模型回答。 | 先找到退款条款，回复时引用来源。 |
| Tool calling / 工具调用 | 模型提出调用某个工具，由程序执行并返回结果。 | 调用“查询订单”；权限仍由程序控制。 |
| Agent / 智能体 | 能根据任务与反馈选择步骤、使用工具的系统。 | 判断下一步该查订单还是补问订单号。 |
| Eval / 评估 | 用固定案例和标准检查输出是否合格。 | 检查有没有编造物流、错用规则或泄露信息。 |

**第一版甚至不需要 Agent。**“接收问题 → 读取事实 → 生成草稿 → 人工确认”这样的固定工作流，更容易理解和检查。等固定流程不能满足需求时，再考虑让模型自主选择步骤。
