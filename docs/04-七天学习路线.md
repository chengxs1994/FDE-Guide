# 接下来七天，每天只完成一个成果

建议每天投入 1–2 小时。完全没写过代码，可以把一天拆成数天；这是一轮项目练习，不代表七天后具备独立交付真实客户项目的能力。

| 天数 | 当天行动 | 完成标志 |
| --- | --- | --- |
| Day 1  <br>弄清问题 | 完成上面的 90 分钟练习。 | 一页需求说明 + 5 条测试记录。 |
| Day 2  <br>学习数据 | 认识变量、列表、条件判断和 JSON；将模拟订单整理成文件。 | 能读懂每个字段，解释缺失字段该如何处理。 |
| Day 3  <br>连接程序 | 有代码基础：用 Python 读取订单并调用模型 API。零基础：先做离线订单查询，不急着调用模型。 | 输入订单号能查到正确记录；不存在时有明确提示。 |
| Day 4  <br>让人能用 | 做一个输入问题、显示依据和草稿的小页面；零基础可先画界面并手动模拟操作。 | 另一人不用读代码也知道如何操作。 |
| Day 5  <br>做评估 | 扩充到 20 条案例，包括缺失、冲突、越权和异常情况。 | 有测试记录，能解释每一条失败；20 条仍只是练习规模。 |
| Day 6  <br>处理失败 | 模拟接口超时、数据不存在、模型调用失败；保留人工处理入口。 | 出错有提示，不伪装成功；能回到人工流程。 |
| Day 7  <br>演示交接 | 邀请一位同伴试用，记录时间和反馈；写使用说明与已知限制。 | 一次完整演示 + 一份别人能照着用的说明。 |

## 开发者的最小实现结构

```text
用户输入
   ↓
程序校验订单号与访问权限
   ↓
读取模拟订单 + 获取适用规则
   ↓
调用模型生成草稿
   ↓
展示依据、草稿和待确认事项
   ↓
人工编辑与确认
```

刚开始用一个后端服务、一个 JSON 文件和一个页面即可。之后再按实际需要加入数据库、检索系统和部署平台。API 密钥放在服务端环境变量中，不能写进浏览器代码或提交到公开仓库。
