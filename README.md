# FDE-Guide · FDE 中文实战指南

面向小白与开发者，从基础概念到动手实践，逐步掌握需求澄清、AI 应用、系统集成与项目交付。

**FDE（Forward Deployed Engineer，前线部署工程师）深入客户的工作现场，弄清问题，动手做出解决方案，并跟进到它能在实际工作中使用。**

本项目从一个虚构的“客服工单助手”开始，串起需求、数据、实现、评估和交接。内容偏 AI 应用方向；FDE 也可以做数据与软件集成，不一定要使用 AI。

## 从哪里开始

- **没有编程基础**：先读岗位解释，再用 AI 对话工具完成 90 分钟模拟练习；之后补 Python、JSON 和接口基础。
- **已有开发经验**：重点练需求澄清、评估、异常处理与交接，把同一个小项目逐步做完整。
- **想持续记录实践**：使用下方模板，记录真实输入、预期结果、失败原因与下一步行动。

## 后续实战计划

以客服与销售为主线，沿着“咨询接待 → 需求了解 → 销售跟进 → 成交交接 → 售后服务”展开，逐步补充可跟做的案例。以下为计划，尚未完成：

### 客服：更快回应，把问题处理完整

- [ ] **常见咨询反复回答，新人找资料慢**：根据产品资料与服务规则生成带来源的回复草稿；资料缺失或过期时提示人工确认，验证回答准确率与处理耗时。
- [ ] **查订单、查物流要切换多个系统**：汇总订单、支付与物流状态，整理客户当前问题和下一步处理建议，减少重复查询。
- [ ] **售后工单分派慢，客户反复描述问题**：从对话中提取问题、已尝试操作和待补材料，生成工单并建议负责人，交接时保留完整上下文。
- [ ] **投诉处理不一致，超时工单容易遗漏**：识别需要升级的问题，提醒处理时限，辅助检查回复是否符合服务规则；退款与补偿由有权限的人员确认。

### 销售：了解需求，持续跟进到成交

- [ ] **咨询线索散落在多个渠道，容易漏跟进**：汇总客户主动提交的需求，去重并补齐来源、负责人和跟进状态，让每条线索都有明确去向。
- [ ] **需求记录不完整，推荐方案不贴合**：从沟通记录整理用途、预算、时间与关键顾虑，列出待确认问题，辅助销售形成有依据的产品或服务建议。
- [ ] **跟进靠个人记忆，交接后信息丢失**：生成沟通摘要、已约定事项和下一步待办，提醒销售按约跟进，消息发送前由销售确认。
- [ ] **方案和报价制作慢，优惠口径不一致**：根据确认的需求、产品目录与有效价格规则生成方案和报价草稿，标出待审批优惠，避免未经确认的承诺。

### 客服与销售协同：接好交接，发现改进机会

- [ ] **成交后承诺没有传递，售后不了解客户背景**：将确认的方案、服务范围、交付时间与特殊约定整理成交接清单，由双方核对后进入服务流程。
- [ ] **咨询很多却不知道客户为什么没买**：汇总常见问题、未成交原因与售后反馈，关联已有的跟进和成交记录，形成可追溯的复盘材料，帮助改进产品说明与服务流程。

优先从“常见咨询回复”和“销售跟进助手”两个小场景开始。每个案例都提供模拟材料、操作步骤、人工确认节点与验收方法，记录准确率、处理耗时、漏跟进情况等实际结果，再决定是否扩大使用。

## 写作与贡献约定

每篇教程尽量包含：**适用场景 → 前置知识 → 输入材料 → 操作步骤 → 验收方法 → 常见失败 → 参考来源**。

- 用中文解释术语，先给具体例子，再展开概念。
- 区分教学模拟、个人建议和已验证事实；不编造效果指标。
- 引用外部教程时保留原作者链接，不整篇搬运。
- 示例仅使用模拟数据；不要提交密钥、客户数据或内部地址。
- 后续新增代码方法需有对应注释。
- 可通过 Issue 提交选题、疑问或失效链接，通过 PR 修正文档。
